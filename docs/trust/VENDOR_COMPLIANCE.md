# Periscan vendor compliance (not customer evidence packs)

**Status:** honest default **None** for vendor SOC 2 Type II  
**Tickets:** P17-4 / #332  
**Real-first:** no fabricated Type II reports, bridge letters, or pen-test PDFs

## Two different things (do not conflate)

| Surface | What it is | What it is not |
| ------- | ---------- | -------------- |
| **Customer SOC 2 support evidence** | Product pack (`SOC2Support` / `SOC2Attestation` storage keys) mapping *customer* measured controls to a **partial** catalog | Not Periscan’s vendor SOC 2 Type II |
| **Vendor SOC 2 Type II** | Independent auditor report about Periscan as a service provider | Not generated by the compliance workbench |

Customer-facing labels use **“Customer SOC 2 support evidence.”**  
Trust & Safety exposes `vendorAssurance.soc2TypeIiStatus`:

| Status | Meaning |
| ------ | ------- |
| `None` | Default. No publishable vendor Type II. |
| `InProgress` | Program underway; no completed report for customers. |
| `ReportUnderNda` | Report exists for NDA-gated sales/security review only. |

Set via `PERISCAN_VENDOR_SOC2_STATUS` (invalid values fail soft to `None`).

## GTM / RFP rules

- Never answer “Do you have SOC 2?” with a screenshot of the customer evidence pack alone.
- If status is `None`, say so and offer product security questionnaire kit (`docs/trust/README.md`) + architecture / isolation proof.
- Expand control matrix depth only when measured mappings exist — catalog remains partial by design.
