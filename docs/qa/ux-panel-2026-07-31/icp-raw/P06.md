## Audit-ready?

**No** — honest **customer evidence-support / audit-appendix** readiness, **not** program-complete control catalogs or an audit opinion system.

You can hand an auditor a PDF that says “not certification / not audit opinion,” maps a **representative** control subset to measured evidence kinds + IDs, and show governance change history. You **cannot** treat Periscan as DORA/NIS2/PCI/ISO/SOC2 program coverage or a GRC SoR.

---

## Would rely for audit support?

**Yes, with constraints** — as a **measured-validation evidence pack** for security-control effectiveness (exposure, detection observation, fix verification, path analysis, integrity), **not** as the compliance program binder, certification path, or TLPT/pen-test substitute.

### 3) Control trace + governance loop is real (persistence, not UI theater) — **strength with role friction**
**Trace:** `computeSnapshotComplianceTrace` derives Met/Partial/Unmet **only** from snapshot evidence + optional continuous schedule + chain integrity (`compliance-catalog.ts` `deriveSnapshotComplianceEvidence` / `computeComplianceCoverage`). Unmet when kinds missing — no free Met.

**Governance API:** owner, evidence request, time-boxed exception (rationale+expiry co-required), Approved requires `reviewNotes`, versioned catalog, append-only change history, audit event, tenant isolation (`packages/shared/src/domain.ts` ~2297–2327; `apps/api/src/services/compliance-governance.ts`).

**Casey friction:**
- Govern mutations require **tenant admin roles** (`requireRole(..., TENANT_ADMIN_ROLES, "govern compliance controls")`) — pure GRC Viewer-class personas cannot run the SoR workflow.
- Measured status table and governance table are **side-by-side but not joined** (sign-off does not require Met; Met does not require sign-off). Good for honesty; bad for “closed control” mental model.
- Export uses latest snapshot only; no period-select or multi-snapshot evidence period binder.
