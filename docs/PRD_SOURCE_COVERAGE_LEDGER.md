# PRD Source Coverage Ledger

This ledger indexes the source PRD before implementation status is considered.
It exists to prevent the failure mode where a broad traceability row, a green
test run, or a "Done" status table hides a product feature that was present in
the PRD but never decomposed into atomic requirements.

This file answers a narrow question: "Has each source section been captured for
source-first audit?" It does not prove the product is complete. Detailed
requirement atoms and implementation status live in
`docs/PRD_REQUIREMENT_LEDGER.md`.

## Coverage Status Legend

- `SectionIndexed`: the source section is represented here, but has not been
  decomposed into requirement atoms yet.
- `NeedsImplementationAudit`: the section has known implementation evidence,
  but source-derived atoms still need direct code/test verification.
- `AtomizedInRequirementLedger`: the section has detailed requirement atoms in
  `docs/PRD_REQUIREMENT_LEDGER.md`.
- `EvidenceMapped`: detailed atoms are mapped to implementation files and test
  evidence.
- `Blocked`: source audit cannot proceed without an external decision,
  credential, legal review, or unsafe action.

## Completion Gate

Do not claim the full PRD or product is complete unless:

- every row in this source coverage ledger is `AtomizedInRequirementLedger` or
  `EvidenceMapped`, or is explicitly `Blocked` with a safe fallback;
- `docs/PRD_REQUIREMENT_LEDGER.md` has zero `Partial`, `NotStarted`, and
  `Unknown` rows;
- full validation passed after the last source, code, schema, migration, test,
  and docs change.

## Current Finding

The immediate reason prior audits overclaimed completion is now explicit:

- Source coverage was incomplete. The atomic requirement ledger existed only as
  a seed focused on the latest missed third-party-tool requirement. It did not
  index the full PRD source section set.
- Validation evidence was sometimes too narrow. Focused tests could pass while
  accumulated-state or concurrent release validation still failed, as shown by
  the 2026-06-28 continuous-validation sweep timeout against a shared
  acceptance database with hundreds of unrelated due tenants.

This ledger closes the source-indexing blind spot. All current source rows are
now `EvidenceMapped`; future PRD source additions must be added here and kept
out of completion claims until they are atomized or explicitly blocked.
Full-completion refreshes still require release-level validation after the final
change, not only focused slice tests.

`pnpm prd:audit` now turns this ledger into an executable status check during
`pnpm verify`. `pnpm prd:audit:strict` fails while any unresolved source rows or
`Partial`/`NotStarted`/`Unknown` requirement atoms remain, which prevents
another broad full-product completion claim from passing on green tests alone.
